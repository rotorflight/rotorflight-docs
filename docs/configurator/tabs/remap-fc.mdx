# Remap FC

Remap FC lets you change which servos, motors, and other functions are connected to which pins on your flight controller — for example, swapping a tail servo output for a motorised tail, adding a buffer pack or onboard glow, or moving a function to a different pin. It's all done from the Configurator, without soldering, rewiring, or building custom firmware.

This is most useful if your board's factory pin layout doesn't quite match how you want to wire your helicopter, or if you're using a board that doesn't have a purpose built Rotorflight target.

## Reading your flight controller

Connect to your flight controller and open the Remap FC tab. Click **Read FC** to load its current wiring. This reads how your board is set up right now — nothing is changed yet.

While it's working, the button label updates to **Reading FC**, and briefly shows a percentage while it restores your existing configuration in the background. You'll also see a loading indicator over the table area until this finishes.

If your board is a recognised Rotorflight reference design, the tab shows its board name and a diagram of the board — including manufacturer branding where available — along with the connector names printed on the board itself (for example "ESC" or "Tail") instead of generic labels. If it isn't recognised, you'll still see every connected function, just with generic names such as "Servo 1" or "Motor 2", and a plain, uncased board outline instead of a branded diagram.

### Supported boards

The current remapper supports the following MCUs, STM32F411, STM32F40X, STM32F7X2, STM32F745, STM32H743, STM32G474. This should cover all Rotorflight compatible MCUs.

If your board's MCU isn't supported (or couldn't be identified), Remap FC shows a **Board not supported** message instead of the table — pin, timer, and DMA changes can't be safely calculated for it yet.

## The pin table

Once your board has been read, you'll see two connected columns:

* **FC Label** – every physical connector on your board, either the board's own printed label or a generic name like "Servo 1".
* **Feature** – every motor, servo, frequency input, and LED strip function currently in use, in a fixed order regardless of which pin it's wired to.

A line connects each Feature to the FC Label pin it's currently wired to, so you can see the wiring at a glance.

Click an **FC Label** entry to open a card showing its pin number, a description, and (where applicable) a **Current Option** dropdown for reassigning it. Click a **Feature** entry instead to open a read-only card describing what that function is for.

Use **Other Pins** below the FC Label column to bring in a connector that isn't currently shown, then choose what you want it to do.

Turn on **Show details** if you want to see the calculated timer and DMA allocation for every function, along with the exact commands that will be sent to your flight controller. **Note: Most people won't need this. It is for information only**.

## Reassigning a function

To change what a pin does, click its entry in the **FC Label** column to open its card, then pick a different function from the **Current Option** dropdown. The function that was previously there is freed up. Motor and servo slots need to be filled in order (for example, Servo 4 can't be assigned until Servos 1–3 are), and some options depend on others already being set up.

A connector that's normally a fixed serial (UART) or I2C port — such as SBUS or TLM — can only ever be set back to its own original job; it can't be handed to a motor or servo, and nothing else can take its place either.

None of your changes take effect immediately — you can make as many edits as you like and review everything before applying them.

## Resolving pin conflicts

Not every pin can be freely reassigned to every function — some pins share internal hardware that can only be used one way at a time. Most of the time, Remap FC works this out automatically in the background as you make changes.

If a change you've made can't work, you'll see a **Pin selection not valid** warning explaining the problem. Where possible, Remap FC will offer a one click suggestion to fix it via **Accept Suggestion** — for example swapping two functions between pins, or moving a function to a free pin. If it can't find an automatic fix, use **Reset to Set Option** to clear the affected function back to unassigned and choose a different pin for it yourself.

You won't be able to apply your changes until any conflict like this is resolved.

## Applying your changes

Once you're happy with your changes, a toolbar appears at the bottom of the page:

* **Save and Reboot** sends your changes to the flight controller and saves them. This also **reboots your flight controller**, which is required for the new wiring to take effect. This is disabled until any pin conflict is resolved.
* **Revert** discards everything you've changed and goes back to what was last read or applied.

Turn on **Show details** to review the **Calculated config** (the resolved timer and DMA allocation for every function) and the **Pending Changes** list of exact commands that will be sent, before committing to them. If any servos end up sharing a timer, a **Servo frequency groups** note tells you which ones — servos sharing a timer must always run at the same rate.

:::caution
Applying changes saves them and reboots your flight controller straight away — there's no separate confirmation step. Double check the Pending Changes list before clicking Save and Reboot.
:::
